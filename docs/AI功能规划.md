# YuMusic AI 功能方向规划

> 目标：让 AI 不只停留在“聊天推荐”，而是真正嵌入播放器的每一次使用。

## 一、现状盘点

- AI 助手面板：自定义接口地址 / API Key / 模型，支持连通性测试与模型列表。
- 可读取登录账号的「我的喜欢」、热曲排行、每日推荐作为上下文。
- 预设指令：喜欢歌单相似推荐、热曲精选、每日推荐精选、专属歌单生成、当前歌曲解读、场景/情绪推荐、音乐冷知识。
- 新增（v1.1.0）：**AI 歌单一键落地播放** —— AI 输出的「歌名 - 歌手」列表可一键在网易云 + QQ 双平台搜索匹配，生成真实可播队列并立即播放。

## 二、已落地（v1.1.0）

| 能力 | 说明 | 状态 |
| --- | --- | --- |
| AI 歌单落地播放 | 解析 AI 推荐列表 → 双平台搜索 → 去重排序（优先精确匹配、免会员）→ 生成队列播放 | ✅ |

## 三、方向矩阵（按 价值 × 可行性 排序）

### P0 推荐先做
1. **AI 电台 / 自动串讲**
   - 描述：AI 根据当前歌单自动编排播放顺序，并在每首歌播放前用文字（后续可接 TTS）介绍歌手与背景。
   - 价值：极高，直接改变“听歌”体验；可行性高（现有队列 + 聊天能力即可）。
2. **AI 歌词意境 → 特效联动**
   - 描述：AI 分析当前歌曲的歌词情绪（舒缓/燃/悲伤），自动切换或微调「商籁 / 星海」的预设、色调、粒子强度。
   - 价值：高，契合本软件“歌词与特效交融”的定位；可行性中（需建立 情绪→特效参数 映射表）。
3. **AI 智能推荐混排**
   - 描述：不只给歌名，还给出“为什么推荐”，并把结果直接混入首页推荐流 / 私人 FM 候选。
   - 价值：高；可行性高。

### P1 值得做
4. **AI 歌单整理与标签**
   - 描述：对「我的喜欢」自动聚类（情绪/年代/语种/场景），生成子歌单并支持一键建单。
   - 价值：中高；可行性中（需要批量歌词/元数据输入，注意 token 成本）。
5. **AI 逐字歌词修复助手**
   - 描述：当检测到词曲不对应时，把该句上下文交给 AI 校准时间轴，结果写回本地歌词缓存。
   - 价值：高（直击现有痛点）；可行性中（LLM 对时间轴数字不擅长，需结构化校验）。
6. **AI 音乐知识问答增强**
   - 描述：当前“解读歌曲”只给文本；可扩展为“这首歌适合什么电影场景 / 同风格冷门佳作 / 创作背景”。
   - 价值：中；可行性高（纯聊天，成本低）。

### P2 进阶方向
7. **语音交互点歌**
   - 描述：Electron 内置 Web Speech API，实现“播放 XX 的 XX”语音指令，识别后走现有搜索播放链路。
   - 价值：中高；可行性中（需处理中文识别准确率与麦克风权限）。
8. **AI 定时 / 场景自动化**
   - 描述：结合现有「声音与定时」：AI 根据“睡前/专注/运动”生成定时播放计划并自动执行。
   - 价值：中；可行性中。
9. **AI 封面 / 视觉生成**
   - 描述：对无封面或自制歌单，用图像模型生成方舟风格封面。
   - 价值：中；可行性低（需要图像生成 API，成本高）。
10. **AI 音质 / 音效建议**
    - 描述：根据歌曲风格建议音质档位、是否开节奏响应、特效帧率档位。
    - 价值：低中；可行性中（输出可一键应用）。

## 四、落地建议

- **统一上下文协议**：为 AI 提供更结构化的当前播放状态（歌名/歌手/进度/队列/特效），让每次问答都能“感知现场”。
- **结构化输出**：推荐类指令强制输出 JSON（`{songs:[{name,artist,reason}]}`），避免解析失败，落地播放更稳。
- **成本控制**：批量分析（如整理喜欢歌单）限制输入歌曲数量，并提示用户预计消耗。
- **本地缓存**：AI 分析结果按 歌曲ID 缓存，避免同一首歌反复请求。
